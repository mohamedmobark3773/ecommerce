# SouqX E-Commerce Backend Architecture

SouqX is a large-scale, production-ready E-Commerce platform. This repository hosts the initialized and scaffolded backend architecture, built with Node.js, Express.js, MongoDB, and Mongoose.

## Architecture Overview

The codebase is structured using **Clean Architecture** principles coupled with a **Feature-Based Modular Design**. This approach maximizes maintainability, testability, separation of concerns, and ease of scaling.

### Design Principles

1. **Separation of Concerns (SoC)**: Each layer has a distinct responsibility.
2. **Feature-Based Modularity**: Instead of grouping files purely by technical layer (e.g., all controllers together), components are grouped by business features (e.g., `auth`, `products`, `orders`). This aligns development with domain boundaries.
3. **Repository Pattern**: Abstracting the data store access layer allows business logic to remain independent of direct MongoDB queries, facilitating testability (using mock repositories).
4. **DTOs and Schemas**: Standardizing input validation and API payload structures using schemas (`joi`/`zod`) and Data Transfer Objects (`dto`).

## Directory Structure

The overall structure consists of a root-level config layer, global shared modules/utilities under `src/`, and individual modular domains inside `src/modules/`.

```text
Back-end/
├── config/                # Global shared configurations (logger, queues, database, socket.io, etc.)
├── database/              # Database connection setups, migrations schema configurations
├── docs/                  # API specification documents (Swagger/OpenAPI docs placeholders)
├── logs/                  # System logs generated by winston logger
├── public/                # Static public assets served by Express
├── scripts/               # Maintenance, build, or deployment scripts
├── seeders/               # Scripts to populate MongoDB with initial system metadata
├── factories/             # Mock data factories for unit/integration testing
├── tests/                 # End-to-End and global integration tests
├── uploads/               # Store directory for local media/file uploads
│
├── src/
│   ├── app.js             # Express application initialization and config loading
│   ├── server.js          # HTTP server wrapper, port listening, and socket.io startup
│   │
│   ├── constants/         # Domain codes, HTTP status messages, error codes, and roles
│   ├── controllers/       # Base controllers and common response helper methods
│   ├── cron/              # Cron scheduling engines
│   ├── dto/               # Global standard DTO classes
│   ├── errors/            # Custom application error definitions (e.g., AppError, NotFoundError)
│   ├── events/            # EventEmitter configurations and global publisher-subscriber lists
│   ├── helpers/           # Small pure utilities for math, arrays, etc.
│   ├── interfaces/        # Common typescript interfaces (if migrating) or schema signatures
│   ├── jobs/              # Global background jobs (e.g., emails, transaction audits)
│   ├── middlewares/       # Global Express middlewares (globalErrorHandler, rateLimiter, requestLogger)
│   ├── models/            # Global database schemas (e.g., shared session models)
│   ├── queues/            # Queue instances (BullMQ manager)
│   ├── repositories/      # Global base repository interface containing generic CRUD operations
│   ├── routes/            # Global API router coordinator mapping /api/v1 prefix
│   ├── schemas/           # Common mongoose schemas shared across domains
│   ├── services/          # Global shared business service utilities
│   ├── types/             # Common custom JSDoc types or Typescript models
│   ├── utils/             # Helper classes for crypto, hash, tokens, or network requests
│   ├── validators/        # Global request validator middleware helpers
│   │
│   └── modules/           # Modulized application features
│       ├── auth/          # Authentication & Authorization modules
│       ├── users/         # Customer and seller account profile management
│       ├── products/      # Catalog items, pricing, inventory
│       ├── categories/    # Product categories tree
│       ├── brands/        # Manufacturer brand entries
│       ├── orders/        # Purchase order workflows
│       ├── orderItems/    # Itemized order details
│       ├── cart/          # Customer shopping cart items
│       ├── wishlist/      # User favorite items lists
│       ├── reviews/       # Product star ratings and feedback
│       ├── payments/      # Stripe integration and checkout sessions
│       ├── coupons/       # Promo codes, discount rules
│       ├── notifications/ # SMS, Email, and Push notification dispatches
│       ├── addresses/     # Multiple delivery/billing addresses management
│       ├── shipping/      # Carrier configurations, tracking info
│       ├── seller/        # Merchant portals, onboarding data
│       ├── admin/         # Site admin controls
│       ├── dashboard/     # Generic landing reporting metrics
│       ├── analytics/     # Product viewing and sales metrics processing
│       ├── chat/          # Real-time message room management
│       ├── messages/      # Text message payloads
│       ├── search/        # ElasticSearch / MongoDB search pipelines
│       └── uploads/       # Profile photo/product media processing module
```

### Module Structure Details

Every domain module inside `src/modules/` follows this standard layout:

*   **`*.controller.js`**: Receives requests, triggers validations, calls services, and formats standard API responses.
*   **`*.service.js`**: Core domain logic, validation flows, and transactional interactions.
*   **`*.repository.js`**: Database interaction queries using Mongoose models. Decoupled from service engines.
*   **`*.model.js`**: Mongoose model initialization and indexing rules.
*   **`*.routes.js`**: HTTP verbs, route paths, middleware chains, and target controller attachments.
*   **`*.validator.js`**: Schema validator functions utilizing libraries like Joi/Zod to parse inputs.
*   **`*.schema.js`**: Structured syntax/rules schema definition for incoming payloads.
*   **`*.dto.js`**: Data Transfer Object mapping class to sanitize and serialize incoming/outgoing data payloads.
*   **`index.js`**: Entry point to export modules and registers controllers/routes.

## Technical Stack & Dependencies

### Core
- **Node.js**: Asynchronous event-driven JavaScript runtime.
- **Express.js**: Fast, unopinionated minimalist web framework.
- **MongoDB & Mongoose**: Object Data Modeling (ODM) library for MongoDB.

### Supporting Libraries (in `package.json`)
- **Security**: `helmet`, `cors`, `express-rate-limit`, `bcryptjs`, `jsonwebtoken`
- **Utility**: `dotenv`, `compression`, `http-status-codes`, `uuid`
- **Validation**: `joi`, `zod`
- **Logging**: `winston`, `morgan`
- **Files/Uploads**: `multer`
- **Async Processing**: `bullmq`, `redis`
- **Real-Time Communication**: `socket.io`
- **Mailing**: `nodemailer`

## Npm Scripts

*   `npm run dev`: Launch the server in development mode using `nodemon` with automatic reloading.
*   `npm run start`: Launch the server in production mode.
*   `npm run test`: Run test suites using `jest`.
*   `npm run lint`: Perform static code analysis using `eslint`.
*   `npm run lint:fix`: Automatically fix ESLint errors.
*   `npm run format`: Standardize code styling format across the workspace using `prettier`.
